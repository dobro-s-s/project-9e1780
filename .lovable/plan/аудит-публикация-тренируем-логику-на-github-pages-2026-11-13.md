## Короткий итог

Опубликовать можно: приложение работает целиком в браузере, без сервера, базы данных и секретов. Но статическая сборка пока **не подтверждена**, и нужны три небольшие правки плюс файл GitHub Actions.

## 1. Статическая сборка с текущей настройкой

- В `vite.config.ts` есть два режима. Без переменной `GITHUB_PAGES_BASE` настройка совпадает с прежней, поэтому версия в Lovable не затронута.
- С переменной включается режим GitHub Pages: без серверной части, с базовым путём, с готовыми страницами `/` и `/tasks`, а также с запасной страницей `404.html`.
- Была одна пробная сборка: код собрался, но готовых страниц получилось **0**. Причина — флаг, который я добавил в команду пробной сборки. Он перенёс файлы во временную папку, а сборщик искал их в обычной `dist/`. Это ошибка самой проверки, а не несовместимость. Но пока сборка не прошла по-настоящему, это не доказано.
- Тот же запуск без флага ещё нужно сделать. Неизвестно и то, работают ли вместе готовые страницы и запасная `404.html`.

## 2. Маршруты / и /tasks

- Обе страницы указаны в списке для сборки. Базовый путь `/project-9e1780/` маршрутизатор TanStack получает из настройки Vite сам, так что `src/router.tsx` менять не нужно.
- Все переходы внутри приложения сделаны через `<Link>`, поэтому базовый путь к ним добавится сам.
- Риск: GitHub Pages переадресует `/project-9e1780/tasks` на `/project-9e1780/tasks/`. Маршрутизатор, скорее всего, уберёт косую черту в конце без перезагрузки страницы. Это нужно проверить в браузере.
- Обновление страницы посреди тренировки сбрасывает прогресс. Так же работает и сейчас.

## 3. Загрузка ресурсов

- Скрипты, стили и картинка с совёнком подключаются через Vite, поэтому получат префикс `/project-9e1780/`.
- Шрифты Google Fonts подключены по полному адресу, с ними всё в порядке.
- Две ссылки начинаются с корня сайта и сломаются на github.io:
  - значок вкладки `"/favicon.ico"` в `__root.tsx` даст 404, и значок не покажется;
  - кнопка «Go home» на экране ошибки (`href="/"`) поведёт на `dobro-s-s.github.io/`, а не в приложение.
- `src/lib/error-page.ts` работает только на сервере, на GitHub Pages он не используется.

## 4. GitHub Actions

- Папки `.github/` в проекте нет, поэтому workflow нужно создать.
- В нём должны быть шаги: checkout, установка bun (в проекте `bun.lock`), `bun install --frozen-lockfile`, сборка с `GITHUB_PAGES_BASE=/project-9e1780/`, файл `.nojekyll`, загрузка `dist/client`, затем `actions/deploy-pages`.
- Нужны права `pages: write` и `id-token: write`.
- В настройках GitHub: **Settings → Pages → Source: GitHub Actions**. Для бесплатных Pages репозиторий должен быть публичным.

## 5. Ограничения TanStack Start

- Серверных функций и API в проекте нет, поэтому статическая версия ничего не теряет. `src/server.ts` и `src/start.ts` сработают только во время сборки.
- Нужна обёртка `@lovable.dev/vite-tanstack-config` версии 2.20.0 или новее, в проекте стоит 2.26.5. Ограничения формата вывода включаются только внутри сборки Lovable, на GitHub их нет.
- Пакет `nitro` в режиме GitHub Pages не используется, но его установка безопасна.
- Сочетание готовых страниц с SPA-оболочкой (`404.html`) в этой версии ещё не проверено. Если оно не заработает, `404.html` можно сделать копией `index.html` при сборке.

## Минимальный план действий (после одобрения)

1. Запустить статическую сборку так же, как её запустит GitHub (без лишних флагов). Проверить, что в `dist/client` есть `index.html`, `tasks/index.html`, `404.html` и что адреса ресурсов начинаются с `/project-9e1780/`.
2. Если готовые страницы не создаются, остановиться и сообщить причину без рискованных обходных решений.
3. Две точечные правки в `__root.tsx`: значок вкладки и ссылку «Go home» строить через `import.meta.env.BASE_URL`. В Lovable это всё так же `/`, поэтому там ничего не изменится.
4. Добавить `.github/workflows/pages.yml` (запуск при push в основную ветку и вручную).
5. Раздать `dist/client` локально по адресу `/project-9e1780/` и пройти в браузере:
   - открытие `/` и `/tasks`, в том числе со слешем в конце;
   - обновление страницы и неизвестный адрес;
   - совёнка, стили и шрифты;
   - все пять заданий до итогового экрана;
   - карточки, разбор и кнопки «Назад» и «Пройти ещё раз».
6. Запустить существующие автотесты и убедиться, что предпросмотр Lovable работает как раньше.
7. Добавить в AGENTS.md правило о режиме GitHub Pages, а в roadmap.md — задачу публикации.

## Что останется сделать в GitHub вручную

- Settings → Pages → Source: **GitHub Actions**.
- Убедиться, что репозиторий публичный.
- После первого запуска workflow проверить вкладку Actions и открыть адрес сайта.
